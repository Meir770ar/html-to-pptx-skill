# חוזה יצוא HTML → PowerPoint

## מקור

סמנו שורש נפרד לכל שקופית ב־`data-pptx-slide`, או השתמשו ב־`.slide` וב־`--slide-per=SELECTOR`. בחרו שורשים ברמה אחת, לא אלמנטים מקוננים. לכל השקופיות חייב להיות אותו גודל. `--layout` מאמת יחס ממדים ואינו מותח תוכן כדי להתאים אותו.

`lang="he" dir="rtl"` למסמך עברי. עטפו כתובות, שמות באנגלית, תאריכים ומספרים מעורבים ב־`bdi` או ב־`dir="ltr"`. השאירו את סדר האותיות הלוגי; אין להפוך מחרוזות עברית ידנית.

- `data-notes="..."` או `[data-speaker-notes]`: הערות מרצה שיועתקו להערות PowerPoint.
- `data-pptx-ignore`: ניווט/כלים שלא יופיעו ביצוא.
- `data-pptx-raster`: רכיב שמותר לשמור כתמונה; זה מדווח וחוסם `--require-editable`.
- `data-pptx-display="grid"`: עוזר להעמיד שורש Grid/Flex שהוסתר ב־display:none.
- `data-fragment`: סדר החשיפות במקור; `--fragments=steps` כולל מצב 0 ולאחריו כל חשיפה לפי סדר DOM.

## מקור אינטראקטיבי או אנימציה

הוסיפו hook שמעמיד שקופית מסוימת במצב יצוא. `index` מתחיל ב־0; `fragments` הוא `final` או מספר חשיפות. `time` נמדד במילישניות. התבנית הכלולה כבר מממשת אותו.

```js
window.__pptxPrepareSlide = async (index, { time, fragments }) => {
  await deck.showForExport(index);
  await deck.seek(time / 1000);
  deck.setVisibleFragments(fragments);
  await document.fonts.ready;
};
```

זו דוגמת ממשק: התאימו את פעולות `deck` למנוע האמיתי; אל תדביקו אובייקט שלא קיים. ה־hook צריך לעצור clocks ו־requestAnimationFrame loops שהמחבר הפעיל, לקבוע מספרים סופיים ולהכין SVG/canvas/video. הממיר מקפיא Web Animations/CSS ומסיר scaling של שורש השקופית, אבל אינו יכול לנחש את מצב האפליקציה שלכם.

למקור HyperFrames הממיר קורא את main-line slides מתוך `application/hyperframes-slideshow+json` ומוציא branch scenes שאינם בקו הראשי. הוא מסוגל להעמיד timeline רשום לפי sceneId בסופו; לכל מקור שמנוהל דרך player/iframe או מנוע אחר כתבו hook במקור הקומפוזיציה עצמו. אין להעביר את wrapper של Studio במקום המקור.

## דיוק ועריכה

`image` משתמש בגבולות האלמנט המדודים ובשטח שמצויר בתצוגת הדפדפן בפועל, ולא בחיתוך viewport בנקודה 0 אחרי גלילה. לכן כל שקופית מצולמת בנפרד גם כשהן חופפות או מוסתרות בניווט. שורש השקופית צריך להתאים ל־viewport; הגדילו `--width`/`--height` עבור שקופית גדולה. הרזולוציה היא `--scale` כפול גודל השקופית. כל התוכן הוא תמונה אחת ב־PPTX; רק שינוי גודל/הזזה של התמונה אפשריים.

`hybrid` מצלם את העיצוב לאחר הסתרת הטקסט הרגיל, ואז מוסיף טקסט נפרד במיקומים שנמדדו. `editable` בונה גם רקעים אחידים, גבולות, טבלאות פשוטות ותמונות נפרדות. טקסט מעורב מחולק למקטעים חזותיים, עם כיוון פסקה ופונט לכל מקטע; עריכת משפט שלם יכולה לדרוש כמה תיבות.

Office ו־Chromium משתמשים במנועי טקסט שונים. אפילו במצב נתמך ייתכנו הבדלי glyph metrics, מרווחים וקו בסיס. אין הבטחת pixel-perfect למצב שניתן לעריכה. למראה המרבי בחרו `image` ושמרו גם מקור HTML. תמונות, סרטונים, WebGL ואפקטים אינם הופכים לאלמנטים וקטוריים נפרדים מעצמם.

היצוא אינו משמר אינטראקציות או אנימציות GSAP/CSS כ־PowerPoint animations. הוא משמר מצב נבחר, או סדרת מצבי חשיפה, ויכול להוסיף מעבר Fade מקורי של PowerPoint. וידאו ביצוא הזה הוא פריים קפוא, לא וידאו משובץ.

## בדיקות ותקלות

הדוח כולל מספר שקופיות המקור והפלט, hash של צילום מקור לכל פלט, פונטים, סוגי אובייקטים, רכיבי raster והערות. הדוח אינו אישור צפייה ב־PowerPoint. קראו אותו ובדקו את הפלט.

ממיר שלא מצליח לטעון תמונה, לגלות שקופית, לשמור יחס ממדים, או לעמוד ב־`--require-editable` נכשל ולא יוצר PPTX חלקי. דוח הכשל נשמר. אין להחליף כשל בתמונה ריקה או ב־"No content found".

Chrome/Edge מותקן מזוהה אוטומטית; אפשר לבחור `--browser=PATH`. מופעל פרופיל דפדפן מבודד ללא שימוש ב־cookies של המשתמש. HTML יכול להריץ JavaScript; הפעילו רק מקור שאתם מורשים לפתוח. URL פרטי אינו נותן לממיר session של הדפדפן האישי.

CLI ישן `--mode=text` ממופה ל־`editable`; `--mode=auto` ממופה ל־`hybrid`. גדלי CSS נשמרים כברירת מחדל. `--font` הוא override מפורש; התקינו את אותו פונט גם ביעד. קלט `-` נתמך עבור stdin; לתמונות יחסיות בו השתמשו ב־base URL מפורש או ב־data URLs.
